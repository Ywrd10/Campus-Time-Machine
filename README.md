# Campus Time Machine / Knight Studio

Knight Hacks IX project: text→video and image→video with synchronized audio, generated by
**Kandinsky 6.0 Video Lite (distilled)** on an AMD Radeon Pro W7900D (ROCm). The frontend is React, TypeScript,
Vite, Tailwind CSS, and Lucide icons; a small Node relay on the laptop forwards jobs to a GPU worker on the
AMD Radeon Cloud instance.

Two workspaces:

- **Campus Time Machine** (default): pick a place on a purple campus map (real OpenStreetMap geometry and official
  UCF coordinates; see [public/maps/README.md](public/maps/README.md)), pick a moment, and watch a photo of that
  spot change. Includes a Journey Wall of finished clips.
- **Free mode**: the original studio, with a free-form prompt, text or image input, and preset settings.

## Run locally

Requires Node.js 22.18+ (the relay imports shared `.ts` files with Node's type stripping).

```sh
git clone https://github.com/Ywrd10/KnightHacksIX.git
cd KnightHacksIX
npm ci
npm run dev
```

This starts in **mock mode**: no backend or env file needed, and every job returns a bundled 6-second sample clip.
Vite prefers http://127.0.0.1:5173 and picks the next free port if needed.

```sh
npm run build    # strict TypeScript + production build into dist/
npm test         # Vitest
npm run preview  # serve the build on :4173
```

## Run against the AMD instance

1. Copy `relay/.env.example` to `relay/.env.local` and set `RADEON_SESSION` (the dashboard's
   `__Host-oneclick-manager` cookie). The relay logs in to the Jupyter gateway itself.
2. In two terminals:

   ```sh
   npm run relay
   VITE_GENERATION_PROVIDER=http npm run dev
   ```

`GET /api/health` reports whether the instance login works and the worker's heartbeat is fresh. Setting up
the instance itself is covered in `AGENTS.md`.

## Supported settings

`src/lib/capabilities.ts` offers only presets that were rendered and timed on the W7900D. The relay accepts
exactly these.

| Resolution | Durations | Model | Measured GPU time (16:9) |
| --- | --- | --- | --- |
| 352p · 640×352 | 2, 3, 5 s | Quality (10 steps) | 36 / 49 / 93 s |
| 352p · 640×352 | 3 s | Fast (6 steps) | 37 s |
| 480p · 864×480 | 2, 3, 5 s | Quality (10 steps) | 69 / 110 / 223 s |
| 480p · 864×480 | 3 s | Fast (6 steps) | 83 s |

- 24 FPS only. 16:9 and 9:16 (portrait swaps width and height).
- Fast is also offered at 2 and 5 s without a time estimate (not benchmarked). Fast audio is about 9 dB quieter.
- Times exclude Qwen prompt expansion (5–16 s) and MP4 export.
- Text→video and image→video only. Images: PNG/JPG/WebP up to 15 MB, resized and center-cropped.
- The Time Machine renders Snapshots only (640×352, 3 s, 10 steps); multi-shot Film isn't available yet.

## Project map

- `src/components/`: Free mode panels (`ModeInputs`, `GenerationSettings`, `VideoOutput`).
- `src/timeMachine/`: Campus Time Machine views, map, places, and moment prompt templates.
- `src/services/generation.ts`, `src/services/timeline.ts`: mock and HTTP adapters.
- `src/hooks/useGeneration.ts`, `src/lib/pollJob.ts`: job lifecycle and polling.
- `src/lib/capabilities.ts`, `src/lib/types.ts`: tested presets, validation, and contracts (shared with the relay).
- `relay/`: laptop-side relay to the Jupyter instance.
- `instance_scripts/`: worker and setup scripts that run on the instance.
- `public/demo.mp4`: the mock-mode sample clip.

No accounts, database, payments, or committed credentials.
